Photo Booth Voucher Integration Plan

เอกสารสรุปการเชื่อมต่อ voucher ระหว่าง Backend, Unity kiosk, และหน้าเว็บ frontend สำหรับระบบ Photo Booth Payment Voucher

สรุป Endpoint ที่ใช้

Admin / Generate Voucher

ใช้ ADMIN_BEARER_TOKEN

ใช้สร้าง voucher code และกำหนดจำนวนครั้งที่ใช้ได้ วันหมดอายุ และประเภทสิทธิ์

POST /api/admin/v1/vouchers/generate

Website / Check Status

ไม่ต้องใช้ token

ใช้สำหรับหน้าเว็บทั่วไปเช็คว่า voucher ใช้ไปแล้วหรือยัง โดยไม่ตัด quota

POST /api/web/v1/vouchers/status

Website / Voucher QR PNG

ไม่ต้องใช้ token

ใช้แสดง QR code ของ voucher รูปแบบ PB-XXXXXXXX ให้ frontend ใส่ใน <img> ได้ทันที

GET /api/web/v1/vouchers/{voucherCode}/qr.png

Unity Kiosk / Validate

ใช้ DEVICE_BEARER_TOKEN

เช็ค voucher ก่อน checkout และคืน checkout_token ยังไม่ตัดจำนวนการใช้งาน

POST /api/kiosk/v1/checkout/voucher/validate

Unity Kiosk / Reserve

ใช้ DEVICE_BEARER_TOKEN

ใช้ voucher จริงและตัด quota ด้วย used_count + 1

POST /api/kiosk/v1/checkout/voucher/reserve

Unity Kiosk / Apply

ใช้ DEVICE_BEARER_TOKEN

ยืนยัน voucher ที่อยู่สถานะ RESERVED หลังจ่ายเงินส่วนที่เหลือสำเร็จ

POST /api/kiosk/v1/checkout/voucher/{redemptionId}/apply

Unity Kiosk / Release

ใช้ DEVICE_BEARER_TOKEN

ยกเลิก voucher ที่ยังเป็น RESERVED และคืน quota ให้ voucher

POST /api/kiosk/v1/checkout/voucher/{redemptionId}/release

Unity Checkout Flow

1. รับ voucher code ผู้ใช้กรอกหรือ scan code ใน Unity kiosk
2. Validate ส่ง job_id, voucher_code, device_id เพื่อรับ checkout_token
3. Reserve ส่ง checkout_token และ idempotency_key เพื่อใช้ voucher จริง
4A. APPLIED ถ้าไม่ต้องจ่ายเพิ่ม ให้ถือว่าใช้ voucher สำเร็จและไปถ่ายรูปต่อ
4B. RESERVED ถ้ายังต้องจ่ายเพิ่ม ให้รอ payment แล้วค่อย apply หรือ release

Decision Logic ใน Unity

validate -> reserve

if reserve.data.status == "APPLIED":
    proceed_to_capture()

if reserve.data.status == "RESERVED":
    wait_for_payment()
    if payment_success:
        apply(redemption_id)
        proceed_to_capture()
    else:
        release(redemption_id)
        show_cancelled()

Idempotency Key

idempotency_key ใช้กันการยิง reserve ซ้ำแล้วตัด voucher ซ้ำ ถ้าใช้ key เดิม backend จะคืน redemption_id เดิม

สำหรับ checkout เดิมที่ retry เพราะเน็ตหลุด ให้ใช้ idempotency_key เดิม แต่ถ้าเป็น job/checkout ใหม่ ต้องใช้ key ใหม่

รูปแบบที่แนะนำใน Unity

{device_id}-{job_id}-voucher-{attempt_no}

ตัวอย่าง

booth-world-tour-01-JOB-20260610-0001-voucher-1
สถานการณ์ ควรใช้ key แบบไหน
กด reserve ซ้ำเพราะ network timeout ใช้ key เดิม
เริ่ม checkout ใหม่หรือ job ใหม่ สร้าง key ใหม่
ผู้ใช้ยกเลิกหลังได้ RESERVED เรียก release ก่อน แล้วถ้าเริ่มใหม่ให้ใช้ key ใหม่

Website Status API

หน้าเว็บที่ไม่ใช่ kiosk ใช้ endpoint นี้เพื่อเช็คโค้ดอย่างเดียว ไม่ต้องใช้ token และไม่ตัด quota

POST /api/web/v1/vouchers/status
Content-Type: application/json

{
  "voucher_code": "PB-XXXXXXX",
  "project_id": "prj_world_tour"
}
Field ความหมาย
usable_now ใช้เป็นตัวหลักสำหรับตัดสินว่าโค้ดใช้ได้ตอนนี้หรือไม่
has_been_used โค้ดนี้เคยถูกใช้ไปแล้วอย่างน้อย 1 ครั้ง
quota_exhausted จำนวนครั้งที่ใช้ได้หมดแล้ว
status AVAILABLE, USED, EXPIRED, NOT_STARTED, INACTIVE, NOT_FOUND

Website Voucher QR PNG

สำหรับ voucher ที่ backend generate แบบ AUTO รูปแบบ PB-XXXXXXXX จะมี qr_png_url ใน response ให้ frontend ใช้ได้ทันที

<img src="https://api.wajanapir.com/api/web/v1/vouchers/PB-ADF2633C/qr.png" alt="Voucher QR">
รายการ รายละเอียด
Endpoint GET /api/web/v1/vouchers/{voucherCode}/qr.png
Token ไม่ต้องใช้ bearer token
รูปแบบ code รับเฉพาะ PB-[0-9A-F]{8} เช่น PB-B0896403
QR payload ข้อความ voucher code ตรง ๆ เช่น PB-B0896403
Response Content-Type: image/png

สถานะสำคัญ

AVAILABLE RESERVED APPLIED RELEASED

สถานะ ใช้ในตาราง ความหมาย Action ต่อไป
AVAILABLE Voucher status API voucher ยังใช้ได้ตอนนี้ Unity เรียก validate/reserve ได้
RESERVED voucher redemption voucher ถูกกันสิทธิ์และตัด quota แล้ว แต่ยังรอจ่ายเงินส่วนที่เหลือ จ่ายสำเร็จเรียก apply, ยกเลิกเรียก release
APPLIED voucher redemption voucher ใช้สำเร็จแล้ว ไปขั้นถ่ายรูปต่อ
RELEASED voucher redemption ยกเลิกการ reserve และคืน quota แล้ว ถ้าจะเริ่มใหม่ให้ validate/reserve ใหม่
